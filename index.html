完整版與簡版

FULL · 四卡

完整版

頁尾「認識專案團隊」四張卡齊備，導流到全部平台。

  • COMPANY　關於瑞禾
  • AGENT　關於現傑
  • PLATFORM　睦聚現傑
  • SERVICE　購廠分析

用途　電子報、已知對象 —— 知道對方是誰、可安心導流。

BRIEF · 兩卡

簡版　<PropCode>b

只留前兩張卡，不導流到睦聚平台與購廠分析。

  • COMPANY　關於瑞禾
  • AGENT　關於現傑

用途　一般散發、同業、屋主 —— 不希望對方順著連結摸清底細時用。

版型統一

八個案子的原稿版型各不相同（八種 hero、八種 footer）。客戶從電子報點不同案， 版面一直變會顯得不專業，因此建置時把每頁的最上與最下換成同一套。 模板取自 TCIP3464（有底圖）與 WangTian5483（文字型）。

HERO
  • 有底圖：室內照 ＋ 深色遮罩，左側瑞禾 LOGO 白底方塊
  • 無底圖：同結構，背景改深綠漸層
  • 金框標籤 → 大標題 → 副標 → 兩顆按鈕（金色電話＋線框次要動作）
  • 下接 KPI 條：深綠底四格金色數字
底圖來源

cases.json 的 hero.image： null 文字型／"keep" 沿用原頁底圖／數字 取頁內第 N 張圖。 現況：關連766、TCIP3464、大埔美 沿用原底圖；工業區21路 取第 0 張；王田5483、中台1300、台中2098 用文字型。

Footer

全站同一份：公司名（中英）、地址、專案負責人 張現傑 0953-909-777、 不動產經紀人字號、免責聲明。公司市話一律不放。

程式

layout.py，由 build.py 在建置時呼叫。 原稿自帶的 hero 與 footer 會被整段換掉，各專案不需要也不應該自己做。 顧問頁 TCIP38-parking 窗口不同，未納入。

三層架構

A properties-src 原稿。各專案 push 到這裡 │ │ build.py 依 cases.json 建置 ▼ B properties 成品。只有「主題行銷頁」對話寫入，網址永遠不變 C properties-admin build.py + cases.json + manifest.json + 本台帳

各專案只碰 A，改完 push 後到「主題行銷頁」對話說一聲「更新 <PropCode>」。 比對原稿 sha256 有變就重建 B，成品網址一個都不會動。

建置指令
cd .../properties-src && git pull --rebase origin main python .../properties-admin/build.py # 檢查 A 有哪些異動沒反映到 B python .../properties-admin/build.py --build # 重建（可加案名只重建指定案）
build.py 自動處理
  1. 移除原稿自帶的團隊區塊，套上標準版
  2. team:full 主版四卡；team:none 不套（顧問頁、已結案）
  3. brief:true 產簡版分身，兩卡＋noindex
  4. 原稿 sha256 記入 manifest.json，供下次比對

命名與鐵則

  • 目錄名 PropCode：地名英拼＋關鍵數字，例 WangTian5483
  • 潛銷案再加四碼亂碼，例 ct1300-e58a，網址不可被猜到
  • 簡版接 b；主目錄已含亂碼後綴者接 -b
  • 上線後不改名、不刪除、不搬家 —— 連結已發出去，斷了就是客戶開到 404
  • 結案物件保留頁面與路徑，只降狀態
  • 各分頁不得連回本台帳，也不得互相連結
  • 對外導流只允許四個：關於瑞禾、關於現傑、睦聚現傑、購廠分析
  • 照片一律 base64 內嵌 —— 單檔要能直接寄送、離線可讀
