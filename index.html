A / B / C 三層架構

A properties-src public，不開 Pages 原稿。各專案 push 到這裡 │ │ build.py（在 C）依 cases.json 建置 ▼ B properties public，開 Pages 成品。只有本對話寫入 https://mac2good909777-commits.github.io/properties/<PropCode>/ C properties-admin private，不開 Pages build.py + cases.json + manifest.json + 本台帳
各專案只碰 A，B 的網址永遠不變。C 只有本人看得到。 日常操作
# 一、看 A 有哪些異動還沒反映到 B cd C:/Claude/projects/properties-src git pull --rebase origin main python C:/Claude/projects/properties-admin/build.py # 二、重建（可加案名只重建指定案） cd C:/Claude/projects/properties python C:/Claude/projects/properties-admin/build.py --build # 三、推送 git add -A && git commit -m "重建 <案名>" && git push origin main
build.py 依 cases.json 自動完成
  1. 讀 A 原稿，移除任何自帶的團隊區塊
  2. team:full → 主版插入完整版四卡；team:none → 不插（顧問頁、已結案）
  3. brief:true → 產簡版分身（亂碼後綴目錄用 -b），兩卡＋noindex
  4. noindex_main:true → 主版也加 noindex
  5. on_index:true → 收進公開總覽，整份自動重生，不要手改
  6. 原稿 sha256 記入 manifest.json，供下次比對是否需重建
新案要做的兩件事
  • cases.json 補一筆設定 —— 沒登錄的案子檢查時會報「A 有新案，cases.json 尚未登錄」，不會漏
  • 本台帳補列（完整版與簡版各一列）
給各物件專案的提示詞在 PROMPT-一頁式收頁.md 的 A 段。

REPO 資料夾管理規範

C:\Claude\projects\properties\ <- git repo（public，只放可公開的成品） ├─ .gitignore 排除 _admin/ ├─ .nojekyll 關閉 Jekyll，保留底線開頭目錄 ├─ index.html 公開總覽（僅列在售案；潛銷／結案不列） ├─ README.md repo 說明 ├─ _admin/index.html ★ 本頁・私人台帳・不 commit └─ <PropCode>/index.html 各物件一頁式（單檔・照片 base64 內嵌）
目錄命名 PropCode
  • 公開案：地名英拼 + 關鍵數字　例 WangTian5483、Guanlian766、TCIP3464
  • 潛銷案：再加 - 四碼亂碼　例 ct1300-e58a（網址不可被猜到）
  • 同案分身：主目錄名後接單一字母　例 WangTian5483b
  • 一經上線 不改名、不刪除、不搬家 —— 連結已發出去，斷了就是客戶開到 404
單一物件 → 收頁流程
  1. 各物件資料夾自行製作，產出一份自足的 index.html
  2. 複製到 properties\<PropCode>\index.html
  3. 潛銷／結案 → 頁內加 <meta name="robots" content="noindex,nofollow">
  4. 在售案 → 於根 index.html 補一張卡片；潛銷、結案 不補
  5. 本頁台帳補一列（上架日 = 首次 commit 日）
  6. git add . ; git commit ; git push → Pages 約 1 分鐘生效
鐵則
  • 各分頁不得連回本頁，也不得連回根 index.html（目前 6 頁皆無回連，維持）
  • 分頁對外導流只允許：about-mac、about（睦聚現傑）、service-demo（購廠分析）、reihe-industrial
  • 照片一律 base64 內嵌，不放獨立圖檔 —— 單檔可直接寄送、離線可讀
  • 結案物件保留頁面，只降狀態，不移不刪
